One-Time Login to App

Send a one-time login link to a bidder by email. If the user does not yet exist on the target site, they are created on the fly from the request fields.

Different server — not the Backoffice API

This endpoint lives on the Bid Server, not the Backoffice API documented in the rest of this site. The base URL, the authentication scheme, and the response envelope are all different from the other endpoints.

  • Base URL (test): https://test-bids-eu.circuitauction.com/
  • Authentication: an api_key query parameter — not the Authorization: Bearer <token> header used elsewhere.
  • Audience: the public-facing bidder app, not the backoffice staff app.
GET /api/login-app-mail
Query Parameters

Always required:

Parameter Type Description Example
api_key string Shared secret configured server-side. Requests without it, or with a mismatching value, return 400 Bad Request. ?api_key=rVpbihBzYpnHgSQu4PArLu9WTubtUVzEPjwWxHHEgf9
mail string The bidder's email address. Validated with FILTER_VALIDATE_EMAIL. ?mail=jane@example.com
site string Site login name. Must resolve to an existing site on the bid server. ?site=acme-auctions
sale_number string Sale number within that site. Must resolve to an existing sale. ?sale_number=2025-03

Additionally required only when the user does not yet exist and must be created:

Parameter Type Description Example
first_name string Given name for the new user. ?first_name=Jane
last_name string Family name for the new user. ?last_name=Doe
phone string Mobile phone number. Stored on the user profile. ?phone=+15551234567
pass string Initial password for the new account. Required by Drupal's user_save(); the bidder normally logs in via the one-time link rather than this password. ?pass=Tmp%21SecurePass
language string Optional UI language for the user (and for the email). Defaults to en. ?language=fr
How it decides: the server looks up a user by mail + site. If a match is found the existing user is reused and the create-only parameters are ignored. If no match is found, all five create-only parameters above must be present or the request fails with Missing required property '<name>'.
Example using cURL
curl -G "https://test-bids-eu.circuitauction.com/api/login-app-mail" \
  --data-urlencode "api_key=rVpbihBzYpnHgSQu4PArLu9WTubtUVzEPjwWxHHEgf9" \
  --data-urlencode "mail=jane@example.com" \
  --data-urlencode "site=acme-auctions" \
  --data-urlencode "sale_number=2025-03" \
  --data-urlencode "first_name=Jane" \
  --data-urlencode "last_name=Doe" \
  --data-urlencode "phone=+15551234567" \
  --data-urlencode "pass=Tmp!SecurePass" \
  --data-urlencode "language=en"
Example using JavaScript
const params = new URLSearchParams({
  api_key: 'rVpbihBzYpnHgSQu4PArLu9WTubtUVzEPjwWxHHEgf9',
  mail: 'jane@example.com',
  site: 'acme-auctions',
  sale_number: '2025-03',
  // Required only when creating the user:
  first_name: 'Jane',
  last_name: 'Doe',
  phone: '+15551234567',
  pass: 'Tmp!SecurePass',
  language: 'en',
});

const response = await fetch(
  `https://test-bids-eu.circuitauction.com/api/login-app-mail?${params}`,
  { method: 'GET' }
);
const result = await response.json();
Success Response
{
  "data": {
    "email sent": true
  }
}

The email is dispatched asynchronously by the bid server; a true response means the request was accepted, not that the message has already landed in the user's inbox.

Error Responses

All validation failures return 400 Bad Request with a Restful-style error envelope. The title field varies:

Cause title
Missing api_keyNo api key has been provided.
Wrong api_keyInvalid api key.
Missing mailNo user e-mail has been provided.
Malformed mailInvalid email.
Missing siteSite must be provided.
Unknown siteInvalid site name: "<name>".
Missing sale_numberSale number must be provided.
Unknown sale_numberInvalid sale number: "<number>".
New user, missing one of mail / first_name / last_name / phoneMissing required property '<field>'
